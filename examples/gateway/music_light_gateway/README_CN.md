# 音乐识别氛围灯网关

[English](README.md)

ESP32-S3 通过数字麦克风听取外部音箱播放的音乐，也可以通过选配的蓝牙接收板直接拿到手机的音乐，在本地做节奏检测，并判断音乐的风格和情绪（愉悦度、能量），用四路 PWM 驱动 RGBW 恒流灯，并通过 Wi-Fi/MQTT 上报和接受控制。

```
外部音箱（AirPlay 等）→ 数字 MEMS 麦克风 → I2S → 节奏/响度（每 16 ms）
手机 → 蓝牙接收板 → I2S ───────────────────↗    → 风格 + 情绪（每 5 s）→ 灯效引擎 → 4 路 PWM → RGBW 恒流驱动
              ↘ 功放 → 喇叭                                        ↘ MQTT 上报
```

## 工作原理

| 环节 | 实现 |
|------|------|
| 采集 | I2S 标准模式，16 kHz，24 位麦克风（INMP441、ICS-43434 等）。蓝牙接收板播放时改用它的数字音频，从 44.1 或 48 kHz 重采样 |
| 节奏 | 512 点 FFT，步长 256（16 ms）；对数谱通量 + 自适应门限检测鼓点；自相关估算 BPM |
| 响度 | 每帧 RMS，带自动增益，音量大小不同都能用满亮度范围 |
| 调性 | 每 64 ms 做一次 2048 点 FFT，折算成 12 个半音的色度分布；每个窗口结束时与大调、小调模板（Krumhansl-Kessler）比对，得到调、偏大调还是偏小调，以及调性是否明确 |
| 风格 | 每 5.12 s 根据速度、节拍规律性、打击感、鼓点密度、频段占比、动态范围和明亮度，判断为 安静 / 氛围 / 古典 / 流行 / 摇滚 / 电子 / 嘻哈 之一；连续两次一致或置信度很高时才切换 |
| 情绪 | 每 5.12 s 汇总 11 个特征：速度、节拍规律性、打击感、鼓点密度、低/中/高频占比、动态范围、明亮度、大小调、调性强度。输出两个 0–1 的连续值：愉悦度（伤感到欢快）和能量（平静到激烈） |
| 灯效 | 风格决定配色和节奏：氛围是缓慢变化的蓝紫，古典是暖白和琥珀，流行是每两拍切换的明亮多彩，摇滚是红橙，电子是每拍切换的霓虹色，嘻哈是紫、金、红。情绪在此基础上调色：欢快时暖色调向金色偏并加暖白，伤感时冷色调向深蓝偏、暖色变柔和并减少白光；偏移有上限，每种风格的配色始终认得出来。能量加快或放慢该风格的换色和渐变，并调整鼓点闪烁的力度。安静时暖白呼吸 |
| 主题 | `vivid` 是上面的鲜艳配色。`song` 是宋式中国传统色，色调含蓄，渐变更慢、鼓点闪烁更柔和：氛围用天青、月白、黛蓝、竹青（烟雨山水）；古典用缃色、牙色、檀色（书斋茶香）；流行用胭脂、藕荷、鹅黄、天青（花间）；摇滚用丹砂、赭石、黄栌；电子用《千里江山图》的石青、石绿、群青和赤金；嘻哈用黛紫、赤金、朱红。用 `theme` 命令或点屏幕中间的日冕切换，重启后保留 |
| 显示 | 圆形 360×360 触摸屏（LVGL），纯黑底：中间是日冕图形，颜色跟随灯光，光芒随响度伸缩、随低音和高音起伏、遇鼓点迸发；中间的暗月上显示风格、情绪和 BPM。拖动外圈调亮度，点日冕切换配色主题，点按钮切换模式。手机连上蓝牙时显示蓝牙图标，音乐来自蓝牙时图标变蓝 |
| 输出 | LEDC 12 位 19.5 kHz PWM（高于可听频率），伽马 2.2，可设最大占空比限制发热 |

**注意：** 风格和情绪的默认判断都是基于规则的基线版本。风格规则在 8 首真实曲目（原始和模拟房间拾音）上，200 个 5 秒片段判对 89 个，常见混淆是古典↔氛围、嘻哈↔电子这类灯效相近的风格。大小调检测在真实录音上可用；但在 8 首真实曲目（模拟房间拾音）上，四象限（平静/欢快/紧张/伤感）与主观标注一致的 5 秒片段约占一半，每个维度平均误差约 0.2。典型的误判是没有鼓的激烈管弦乐（比如匈牙利舞曲），会被判成伤感而不是紧张。建议用你自己房间的录音和你自己的标注把两者都校准一次（见下文）。

## 引脚分配（ESP32-S3-WROOM-1 N16R8 建议）

| 功能 | GPIO | 说明 |
|------|------|------|
| 麦克风 BCLK / WS / DIN | 4 / 5 / 6 | Kconfig 可改 |
| 灯 R / G / B / W PWM | 38 / 39 / 40 / 41 | 接恒流驱动的 DIM 脚，Kconfig 可改 |
| 按键 | 0 | 单击切换 音乐/固定色/关，长按 5 s 重启 |
| 圆形屏 QSPI | CS 10, CLK 12, D0 11, D1 13, D2 14, D3 9, RST 8, 背光 7 | ST77916，Kconfig 可改 |
| 触摸 I2C | SDA 15, SCL 16, INT 17, RST 18 | CST816S，Kconfig 可改 |
| 蓝牙接收板 I2S 输入 | BCLK 1, WS 2, DATA 47 | 接接收板的 I2S 输出，Kconfig 可改 |
| 蓝牙接收板 UART | TX 42, RX 21 | 连接状态和歌名，Kconfig 可改 |
| USB 调试 / 下载 | 19 / 20 | 内置 USB-Serial-JTAG |
| 不要使用 | 3, 45, 46（启动配置脚）；35, 36, 37（八线 PSRAM 占用） | |

38–41 同时是外部 JTAG 引脚；调试走内置 USB-JTAG 就不冲突。

## MQTT 主题

前缀 `<base>` = `<prefix>/<gateway_id>`，默认 prefix 为 `music-light`。

| 主题 | 方向 | 内容 |
|------|------|------|
| `<base>/status` | 上报 | 保留消息 `online` / `offline`（遗嘱） |
| `<base>/music` | 上报 | 每 5 s：风格和置信度、情绪象限、愉悦度、能量、BPM、规律性、大小调、调性强度、响度、频段占比、特征向量，以及音源（`mic` 或 `bt`） |
| `<base>/light/state` | 上报 | 保留消息：模式、配色主题、当前风格、亮度、固定色 |
| `<base>/bt` | 上报 | 保留消息：蓝牙接收板是否连接、是否在播放、采样率、歌名、歌手 |
| `<base>/telemetry` | 上报 | 运行时间、内存、RSSI |
| `<base>/cmd` | 下发 | 见下表 |
| `<base>/resp` | 上报 | 命令回复 |

| 命令 | 作用 |
|------|------|
| `mode music` / `mode static` / `mode off` | 切换模式 |
| `color 255 120 0 50` | 固定色 R G B W（0–255），自动切到固定色模式 |
| `brightness 60` | 亮度 0–100 |
| `theme song` / `theme vivid` | 配色主题，重启后保留 |
| `label rock happy` / `label pop 0.3 0.9` / `label none` | 给接下来的 `/music` 消息打上校准标签：风格（`ambient`、`classical`、`pop`、`rock`、`electronic`、`hiphop`）、情绪（`calm`、`happy`、`tense`、`sad`，或 0–1 的愉悦度和能量），或两者都给 |
| `ping` / `info` / `reboot` | 诊断 |

## 编译

需要 ESP-IDF v5.4 及以上。

```bash
idf.py set-target esp32s3
idf.py menuconfig   # Music Light Gateway：Wi-Fi、服务器、麦克风、灯和屏幕的引脚、功率上限
idf.py build flash monitor
```

日志每 5 s 打印一行分析结果，可以直接用来对照现场效果调参。

## 圆形屏

默认屏幕是常见的 1.8 寸 360×360 圆形屏：ST77916 主控走 QSPI，触摸芯片 CST816S。屏幕刷新的优先级低于音频分析和灯光，画面再忙也不会耽误鼓点。触摸芯片没有响应时屏幕照常显示，只是不能触摸；屏幕本身起不来时，灯照常工作。不接屏幕时可以在 menuconfig 的 *Round touch display* 里关掉。

不同厂家的 ST77916 屏有时需要各自的初始化命令；如果屏幕黑屏或颜色不对，把厂家给的初始化序列填到 `display_ui.c` 里的 `st77916_vendor_config_t.init_cmds`。如果触摸位置左右或上下反了，在 menuconfig 里打开对应的镜像选项。

固件开启了八线 PSRAM（N16R8 模组自带），模组没有 PSRAM 时也能正常启动。应用分区为 3 MB，4 MB Flash 即可放下。

## 蓝牙接收板

ESP32-S3 没有经典蓝牙，手机不能直接把音乐传给它。这部分交给一块 ESP32 板子（ESP32-WROOM-32 之类），烧录 [bt_receiver](bt_receiver) 里的固件：手机搜索并连接“Music Light”，音乐经 I2S 功放（比如 MAX98357A）从喇叭放出来。网关在同样三根 I2S 线上旁听，拿到的是手机发出的原始音乐，不受房间回声影响；接收板还通过 UART 上报连接状态和当前歌曲。

| ESP32 接收板 | 功放 | ESP32-S3 网关 |
|--------------|------|---------------|
| GPIO 26 BCLK | BCLK | GPIO 1 |
| GPIO 25 WS | LRC | GPIO 2 |
| GPIO 22 DOUT | DIN | GPIO 47 |
| GPIO 17 TX | | GPIO 21（RX） |
| GPIO 16 RX | | GPIO 42（TX） |
| GND | GND | GND |

```bash
cd bt_receiver
idf.py set-target esp32
idf.py build flash monitor
```

接收板有声音输出或报告正在播放时，分析改用蓝牙音频；音乐停止 3 s 后回到麦克风。手机发 44.1 或 48 kHz，网关根据位时钟自动测出采样率，再重采样到 16 kHz。接收板是选配，默认关闭，需要时在 menuconfig 的 *Bluetooth receiver board* 里打开。它只在手机把音乐发给它时有用，所以要么板子接功放和喇叭，要么手机能同时连两个蓝牙设备（比如三星的双音频输出），否则现场听不到声音。音乐从手机自带喇叭或智能音箱放出时，用麦克风收音就行。

## 静音门限

常见 MEMS 麦克风灵敏度为 -26 dBFS（94 dB SPL），房间里 60–80 dB SPL 的音乐大约是 -60 到 -40 dBFS，安静房间在 -80 dBFS 以下，所以默认静音门限设为 -65 dBFS。装好后看 `/music` 消息里的 `level_db`：音乐播放时应明显高于门限，不放音乐时应低于门限，否则在 menuconfig 里调整 `AUDIO_SILENCE_DB`。

## 校准风格和情绪判断

分析代码不依赖 ESP-IDF，可以在电脑上编译运行。校准步骤：

1. **采集。** 用网关自己的麦克风在实际房间里采集最准确。每种关心的风格、每个情绪象限都至少放 3 首不同的歌，每首放 1 分钟以上，给每首歌标上风格和你自己的感受：

   ```bash
   cd host_test
   pip install paho-mqtt
   python3 collect_mqtt.py --broker <服务器> --id <网关id> -g genre.csv -m mood.csv
   # 每换一首歌发一次（标签相同也要重发，用来区分不同的歌）：
   mosquitto_pub -h <服务器> -t 'music-light/<网关id>/cmd' -m 'label rock happy'
   # 只给风格、只给情绪，或直接给情绪数值（先愉悦度后能量）也可以：
   mosquitto_pub -h <服务器> -t 'music-light/<网关id>/cmd' -m 'label pop 0.3 0.9'
   # 结束后：
   mosquitto_pub -h <服务器> -t 'music-light/<网关id>/cmd' -m 'label none'
   ```

   也可以用录音文件：`./analyze_wav --csv rock song.wav >> genre.csv`、`./analyze_wav --csv happy song.wav >> mood.csv` 或 `--csv 0.3,0.9`（先用 `ffmpeg -i song.mp3 -ac 1 -ar 16000 -sample_fmt s16 song.wav` 转格式）。

2. **训练和评估。** 两个脚本都按“每次留出一首歌”评估，没训练过的歌也要判对才算数；情绪脚本还会在同一批数据上列出内置估计的误差作对比：

   ```bash
   python3 fit_genre_model.py genre.csv
   python3 fit_mood_model.py mood.csv
   ```

3. **写入固件。** 只有训练出的模型比内置规则更好时，才生成对应的模型头文件，重新编译烧录，设备会自动改用训练好的模型：

   ```bash
   python3 fit_genre_model.py genre.csv -o ../main/genre_model.h
   python3 fit_mood_model.py mood.csv -o ../main/mood_model.h
   ```

只采集了部分风格时，风格模型只会在这些风格之间选择。歌太少时训练出的情绪模型通常不如内置规则，某个象限少于 3 首歌时脚本会提示。其他工具：`make test` 跑合成音乐自测，`./analyze_wav song.wav` 打印与设备相同的逐段分析。
